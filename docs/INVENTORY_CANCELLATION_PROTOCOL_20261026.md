# Deterministic inventory cancellation protocol

Task8 specification preparation. This resolves the scheduling design left open in PR197; it does not execute or implement either future inventory API.

Use an unexported per-invocation observer parameter on the future private core. The public BuildRequiredInventory/AdmitRequiredEvidence wrappers always pass nil. No global variable, context.Value option, environment flag, exported hook, callback payload or production caller-controlled observer is introduced. The observer receives only a closed phase enum; it cannot inspect or mutate a result. The test-only caller invokes the same core, and healthy nil-observer/public-wrapper runs must match the independently frozen literals. This is a deliberate internal test seam, not a new public API or authentication mechanism.

Fixed phase names: after-input, after-derived-work, before-return. For Build these mean after complete raw validation, after sorted requirements are derived, and immediately before publishing a result or fixed error. For admission they mean after complete typed input validation, after existing projections complete, and immediately before publishing a result or fixed error. The implementation must report each reached phase once, in that order, with a context check immediately after notification. All normal loop/entry/context checks remain required. Phase notification never replaces those checks.

The harness selects the phase from a frozen literal, cancels synchronously inside the observer, and verifies that exact phase was reached once. No goroutine race, sleep, wall-clock delay, production-derived poll count or recalibration is allowed. Before-return cases independently exercise both healthy and fixed-invalid tails. Every terminal result is nil, with errors.Is(err, context.Canceled) or errors.Is(err, context.DeadlineExceeded), never a fixed input error. Already-expired standard context.WithDeadline and ordinary context.WithCancel cover real context behavior at entry. A deterministic virtual-clock Context covers the late deadline signal; it must keep Deadline/Done/Err stable and is explicitly a simulation, not a real-timer test.

The [standalone scheduler model](evidence/20261026/inventory-freeze/cancellation-model.go.txt) uses no product imports. Its16reachable positive terminal schedules,16deliberately faulty schedules, two healthy controls and four scheduler-misuse controls establish that this scheduling protocol can distinguish terminal priority from success/fixed-error escape. They do not establish that absent product APIs implement the checkpoints. Future phase-specific tests must reject a compiling reversal that bypasses terminal handling and require the intended assertion, rejecting panic/build/infrastructure/timeout/restore failures under the open R7-F04 corrective assurance obligation.

The [official Go Context contract](https://pkg.go.dev/context#Context), checked26October, defines stable Deadline/Done/Err and concurrent context use. It advises against passing optional behavior in context values. The pinned Go1.26.10source/runtime is the execution reference; no toolchain/dependency/source pin is refreshed. The new observer is private, per-call and nil in production. Separate testing must show observer absence has no behavior/cost-visible output effect and no diagnostic aliases escape.

Task8freeze requires this protocol and its literal schedules to be included in the supplemental consumer descriptor. Actual public-wrapper/core equivalence, phase callbacks and compiling reversal proof belong to task9 after its required first published missing-API consumer observations on both hosts. Do not label the standalone model as future API coverage.

The invalid raw/typed tail fails before successful input admission, so only before-return is reachable on that error branch. The success branch has all three phases. An initial standalone model placed the invalid error after all phases; reconciliation corrected that artificial branch to16reachable schedules, without modifying any original50or supplemental26expected result. Never require an observer phase the real validation order cannot reach.

Terminal error means ctx.Err() (Canceled/DeadlineExceeded), consistent with existing projectors, not arbitrary context.Cause metadata. WithCancelCause custom payload must not replace or leak through the canonical terminal sentinel.
