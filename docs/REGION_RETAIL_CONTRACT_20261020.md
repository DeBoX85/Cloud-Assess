## Admission and deterministic selection

Validate request before HTTP: nonzero clock, at most 8,192 unique nonempty meter IDs (512-byte safe UTF-8 cells), one to 32 unique canonical physical region IDs, bounded aggregate request text 4 MiB. Meter IDs are opaque, case-sensitive identities; do not infer GUID shape. Empty meter list completes without HTTP after request validation. Regions use existing canonical regex/physical-region exclusion. Bound all text/JSON before generic materialization; reject invalid UTF-8, controls/replacement/noncharacters, case-fold duplicate object keys, trailing JSON, nonfinite/overflow/underflow nonzero numbers and excessive nesting. Unknown fields remain forward compatible only within all text/numeric/work bounds. Known fields use the same case-fold identity as Go JSON; aliases must not hide continuation or required fields.

A page is atomic: on malformed field/row discard that page, retain earlier diagnostics only, and return a fixed safe failure code. Every item requires nonempty meterId/meterName/productId/skuName/unitOfMeasure/currencyCode/type/armRegionName; currency exactly USD, type exactly Consumption, tier/retailPrice/unitPrice finite, nonnegative and at most 1e12, retailPrice equal unitPrice. Required numeric fields and isPrimaryMeterRegion must exist with correct types, no null coercion. Optional display fields are safe strings when present; metadata must be primary. A malformed unrelated/nonpositive item still fails its page. Dates are absent/empty (oldest) or valid RFC3339 instants; compare parsed instants in UTC. Exclude future items in both phases. Normalize item region using source lowercase/remove ASCII spaces, then require canonical physical format. Irrelevant but valid regions may be ignored; no country-to-region guess.

Metadata: among currently effective requested original IDs select minimum tier. At that minimum, exact identity tuple, unit, normalized originating region and ancillary identity/display fields must agree across all rows; identical repeats are harmless. Conflicting minimum-tier metadata makes that original unresolved, independent of response order. A later lower tier supersedes higher-tier conflicts. Never use an unresolved or foreign meter in a pricing request.

Pricing: match exact triple, selected tier and exact UoM to every original that shares the tuple; preserve original ID and target ID separately. Record UoM mismatches. Omit nonpositive prices, irrelevant regions and future instants from eligible selection. For each original/region choose latest effective instant; equal-latest differing price or distinct target identity/metadata is a conflict and excludes that cell. A strictly later unambiguous record may supersede an earlier conflict. Identical records deduplicate. Sorting and deterministic diagnostics cannot depend on map iteration or arrival order.

Complete means all batches/page chains ended without error and every requested original has unambiguous metadata plus one eligible resolved price for EVERY requested region. Empty results are PARTIAL, not proof that an unsupported or free service is equivalent. A legitimate zero retail price is retained diagnostically but excluded, matching the source's positive-price rule. Any unresolved/missing/conflicting cells return PARTIAL/retail_incomplete and export no eligible maps. An invalid/failed first page returns UNKNOWN; failure after any admitted page returns PARTIAL. Hard caller cancellation returns nil/error. Input/constructor misuse returns nil/fixed safe error before HTTP. Error codes are retail_request_failed, retail_response_invalid, retail_decode_invalid, retail_continuation_invalid, retail_limit and retail_incomplete; never include provider text.
