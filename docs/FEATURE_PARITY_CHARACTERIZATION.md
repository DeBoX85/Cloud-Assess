## External YAML queries are distinct from internal plugin tables

The pinned source has two extension contracts. YAML plugins contain recommendation queries that join the ordinary Graph recommendation/findings path. Internal Go plugins produce separate named tables. The word plugin does not imply a subprocess or arbitrary executable loader: the inspected production loader discovers YAML, while built-in Go scanners implement an interface compiled into the binary.

Missing directories are skipped; invalid candidate files are debug logged and skipped. First discovered YAML name wins. | No production discovery. Define the neutral branded directory and explicit-path policy before exposing execution; preserve known discovery precedence or record a deliberate change. |

## Failure and report contract before execution

The source [plugin execution stage](https://github.com/DeBoX85/azqr/blob/8e4f0577f3615e6c9014c031bcad079f235369cc/internal/pipeline/stage_plugin_execution.go) logs a scanner error, continues and returns nil. Several scanners also log and skip individual failures. Copying this behavior would conflict with the target's explicit completeness/stage health contract. Preserve healthy assessment semantics, but record failure/partial evidence and exit policy as a deliberate target correction with regressions; never turn access denial into certified empty data.

Internal output carries metadata, sheet name, description and header-plus-row tables. Source JSON stores a list of externalPlugins, including all sheets for a plugin. CSV names use sheet names and Excel renders each sheet. Target canonical results have no production plugin-table contract yet. Define additive/versioned canonical ownership, report privacy, row widths/types, safe filenames/sheet collisions, formula handling, redaction and bounded size before wiring an adapter. Preserve multi-sheet output; do not reduce plugin tables to invented generic findings. Extend semantic comparison deliberately before claiming plugin equivalence.

Source `region-selection` stores client/cache/regions/history on a registered scanner instance. Target per-run state must avoid cross-run contamination and races. Reuse target origin guards, selected cloud/audiences, no-registration options, pagination/cancellation and secure report staging rather than import less restrictive source client construction.
