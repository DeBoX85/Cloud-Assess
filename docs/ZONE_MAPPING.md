# Zone mapping migration contract

Status: B3 adapter implementation in progress, 2026-10-02. This first slice is an internal adapter, not a CLI command or a completed plugin migration. Canonical table/schema, report privacy, mixed/plugin-only execution and honest plugin discovery are subsequent B3 acceptance steps. Existing CLI plugin availability remains unchanged.

## Source and API evidence

Pinned AZQR `8e4f0577f3615e6c9014c031bcad079f235369cc`, `internal/scanners/plugins/zone/mapping.go`, `types.go` and `internal/az/locations.go` define the five columns: Subscription, Location, Display Name, Logical Zone, Physical Zone. Each availability-zone mapping produces one row. Locations without mappings produce no rows. Sort by subscription display name, location and logical zone; add subscription ID, physical zone and display name only as deterministic tie breakers. Preserve source metadata/provenance when the table framework is implemented.

The [Microsoft List Locations 2022-12-01 contract](https://learn.microsoft.com/en-us/rest/api/resources/subscriptions/list-locations?view=rest-resources-2022-12-01) documents a UUID subscription ID, GET `/subscriptions/{id}/locations`, `value`, nested `availabilityZoneMappings`, and a `nextLink`. No resource provider registration, resource mutation or extended-location request is needed.

Confirmed source limitations: the pinned implementation ignores nextLink and logs/skips subscription errors while returning success. The target follows safe continuations and retains valid earlier pages/other subscriptions with explicit failure codes. Missing/null value, null location/mapping objects or missing zone identity fail that page rather than claim valid emptiness. Duplicate keys (including case variants), invalid UTF-8 and JSON nesting deeper than 64 are rejected. Unknown additional API properties remain allowed. Valid `value: []` is complete empty data. The target accepts an explicitly selected HTTPS ARM origin instead of hardcoding the public cloud.

## Request, ownership and limits

Only the selected origin and exact subscription locations path may be requested. Validate UUIDs and the entire scope before any request. Validate each continuation before the HTTP client can authenticate: HTTPS, same authority, no user/fragment/backslash/encoded path, unchanged subscription path, exactly one unchanged API version. Continuation query parameters are opaque, not logged. Relative continuations resolve against the initial request and undergo the same checks. Repeated links and excessive pages fail explicitly. The production HTTP client disables redirects; injected getters/transports are trusted code and must honor context, byte bounds and redirect controls.

Five workers at most; context-aware scheduling, no goroutine per subscription and no mutable cache across runs. Bound one request body (including HTTP error bodies) to 1 MiB, one subscription to 64 pages, 8 MiB and 2,048 rows, selected scope to 256 subscriptions, and aggregate accepted rows to 65,536. Limit violations return explicit failures, never a complete truncated result. Already accepted rows survive later-page failures. These are adapter safety ceilings, not representative load certification or universal bounds on SDK retries, hostile injected code, all application stages or output formats. Per-subscription buffers are bounded; aggregate admission follows sorted subscription ID for deterministic behavior.

The new bounded GET helper owns closing every response and the operation deadline. Existing GET/POST behavior is unaffected. The adapter exposes typed rows and per-subscription sanitized failure codes, not provider response text, continuation tokens or formatted reports. Caller maps and returned slices do not become shared state. Before public exposure, stage health/exit behavior, source table projection, redaction and every relevant format must pass their own acceptance checks.
