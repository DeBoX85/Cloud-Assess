A synthetic HTTP403 produces the same header-only output as successful empty scope: source logs/skips batch errors without output health. Empty subscriptions still request the available dates. Preserve these findings, not silent target success. Future request adapter must follow bounded same-endpoint opaque pagination, detect cycles/limits/ambiguous envelopes, classify access decisions, retain valid batches/pages with failed or warning health and preserve context identity. Validate actual API/SDK access-decision names before implementing them. Do not infer access completeness from empty rows or invent universal role/sovereign service availability.

The pure candidate preserves valid source arithmetic and received item accumulation order, deterministically sorts final exact labels and returns owned canonical tables. It rejects reversed/invalid service date ranges, invalid/control/noncharacter/over-512-byte labels, nonfinite values and aggregate/ratio overflow; malformed items count as warnings without losing valid items. Fatal/context failure retains previously aggregated rows and warning counts. These are explicit safety corrections, not source parity failures. Filter callbacks/injected application code are trusted and must honor context; no sandbox/hard deadline guarantee.

Budgets: 65,536 input items, 4,096 aggregate types, 16 MiB cumulative input label bytes and 512 bytes per label. Canonical table limits remain enforced. The future adapter must bound request subscriptions, attempts/pages/body/total bytes/context and access metadata separately; these are not implemented by the pure projection. No new dependency, SDK upgrade, pricing query or Azure call.
